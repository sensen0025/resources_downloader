# download-and-verify（确定性下载 + 验证交付）

下载是执行层的确定性动作，调用本仓库插件的通用工具即可；**不要每次现写下载代码**。

## 1. 直链 → download_file
- 适用：`.zip/.pdf/.mp3/.mp4/.png/…` 单文件直链、以及爬虫解析出来的任何「内容型」URL。
- 传参要点：`url`、`out_dir`（默认 downloads/）、`out_name`（按扩展名推断，注意 Content-Disposition）。
- 该工具自动：分块 Range 断点续传（中途断了重跑续传）、算 sha256、存 `*.part` 后改名。失败会回报 HTTP 状态，据此换源或补头。

## 2. m3u8/流媒体 → download_hls
- 适用：解析出的 `.m3u8` 主/子清单、播放页内嵌流。
- 给 `m3u8_url` 与可选 `out_name`；主清单默认取最高清晰度（或显式指定）。工具自动拉分段、解 AES-128、合并；系统有 ffmpeg 时合并成 mp4，否则输出可播放的 TS 拼接文件。
- 只接受你（agent）确认过的流地址；不要对非流 URL 调用。

## 3. 验证 → probe_file
落地后**必须验证**再交付：
- `probe_file(path)`：返回 大小/扩展名/魔数/类型/是否疑似文本/可选 sha256。
- 检查点：非空；扩展名与魔数一致（PDF 以 `%PDF` 开头、PNG 以 `\x89PNG` 开头等）；大小与 HTTP Content-Length 匹配；下载失败的 HTML 错误页（如「404 Not Found」文本被存成 `.mp4`）必须当场识破。
- 列表/批量任务：对**每一项**都 probe，不能只验第一个。

## 4. 交付
给用户明确结果（可 JSON）：
```jsonc
{
  "ok": true,
  "file": "downloads/xxx.mp4",
  "sizeBytes": 1234567,
  "type": "video/mp4",
  "sha256": "…",
  "matched": "exact | near-miss",
  "note": "来源: https://…; 清晰度: 1080p"
}
```
- 交付内容要能被复核：路径真实存在、校验值正确、来源可追溯。
- **近似交付（合法）**：请求的精确规格/清晰度/格式/版本不可得时，可交付**同一资源最接近的可验证变体**
  （如最高公开档 1080P 替代请求的 4K），但必须：`probe_file` 验证实际文件有效、`note` 写明差异、
  `matched:"near-miss"`。跨类型偷换（把别的资源冒充目标）不算完成。
- 失败：如实说明是哪一步挂的（解析/下载/验证），把 HTTP 状态、抓到的响应片段留给用户判断，不要给“假成功”；
  多次失败后按 `task-termination` 收尾，不必无限重试。

## 5. 安全边界
- 不执行/解压/打开下载物的内容（本仓库不做查毒）；对可疑脚本类文件在交付时加一句提醒。
- 下载目录、临时文件在仓库 `.gitignore` 内，绝不把用户资源提交入库。
