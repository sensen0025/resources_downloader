# task-termination（自主收尾 + 近似交付）

你不需要「一直试到用户喊停」。判断希望不大、预算将尽时，**主动收尾**是正确行为——但要把结尾收干净。

## 1. 何时收尾（满足其一即可，不用等用户）
| 信号 | 说明 |
|---|---|
| 策略穷尽 | 已换 **≥3 条不同策略**（换源/换接口/换格式/换站/换工具），均无实质进展 |
| 调用空转 | 连续 **≥8 次**工具调用只产出同类失败、无任何新信息（新状态码/新页面特征/新候选都算“新信息”） |
| 预算将尽 | 上下文/输出预算所剩不多，继续尝试会挤掉收尾与交付的篇幅 |
| 决定性障碍 | 已确认 403/登录墙（且无凭证可给）/资源下架或不存在/服务彻底不可达，证据在手 |
| 用户喊停 | 立即停 |

## 2. 收尾三选一（不许空手糊弄）
1. **拿到货** → 正常交付：`FINAL_JSON:{"path":"绝对路径","size":N,"note":"来源与规格"}`。
2. **只有近似** → 按下方「近似交付」规则交付，并显式注明差异。
3. **确实没有** → `FINAL_JSON:{"error":"原因"}`，但在此之前把以下写进输出/记忆：
   - 已试过什么（关键词/站点/接口/工具，各到什么状态码或报错）；
   - 卡点证据（HTTP 状态、响应片段、登录墙种类）；
   - 下一步建议（需要用户提供什么：Cookie/直链/换源/允许哪种近似）。
   再 `memory_remember` 记录该域结论（成功失败都记，见 site-memory）。

## 3. 近似交付（放宽目标：允许轻微差异）
- 请求的精确规格/档位不可得，但存在**同一资源**的其它可验证形态时，允许交付**最接近的可验证变体**，
  而不是空手失败。典型放行差异：清晰度/分辨率档位、码率、格式（mp4↔webm、zip↔7z）、
  音轨/字幕语言、版本号、来源镜像/站点不同、文件被切分打包。
- 规则：
  - 先问/推断用户最在意哪个维度（体积小 vs 清晰度 vs 格式兼容）。推断不了且差异明显时，交 best-effort + 注明，别卡住等答案。
  - 交付物**必须真实下载并 probe 验证**（大小/魔数/类型非空有效），证明“这确实是个文件”，不许拿 HTML 错误页凑数。
  - note 必须写明差异：`note:"请求 4K，站点最高公开档为 1080P，已交付 1080P（near-miss）"`；可带 `"matched":"near-miss"`。
- **边界（不许放行）**：跨类型偷换（要图片给 exe、要 PDF 给 txt 伪冒）；编造不存在的档位；把 A 资源当 B 资源交付。
  拿不准是否算“同一资源”时，如实交付“找到了相关但不确定是否你要的”，把选择权给用户。

## 4. 收尾动作清单
1. 有产出 → 交付 JSON（path/size/note，必要时 matched）；
2. 无产出 → FINAL_JSON error + 上面第 2 点的证据/建议；
3. `memory_remember` 打分收口（成功/近似/失败都记，附日期）；
4. 输出里避免无意义长复盘——收尾是“干净结束”，不是“写小作文”。
